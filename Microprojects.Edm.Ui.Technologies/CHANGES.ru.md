# Основной UI EDM — изменения для пользователей

Основной UI — это домашний экран EDM: панель управления, мастер New Operation, деревья настроек (workbench'и, устройства, профили, процессы, аудиты) и карточка операции с отчётами по сенсорам. Смонтирован в корне сайта.

## v2.0.0.0

- **Master-дерево — drop на пустое место и обновление при удалении папки** (PR #70). Перетаскивание узла на пустое пространство вне любой цели раньше молча ничего не делало в деревьях настроек Devices, Workplaces, Hosts и Process; drop теперь делает fallback на видимый локальный корень, чтобы перемещение всегда приземлялось куда-то осмысленное. Удаление папки также перезагружает дерево, чтобы папка исчезала сразу.
- **Переключатель плотности теперь масштабирует весь UI** (PR #65). Плотности Compact, Comfortable и Touch раньше подвинут небольшой набор токенов строк и полей; теперь они применяют фактор `zoom` к корню страницы (Compact = baseline, Comfortable +15%, Touch +32%), поэтому текст, отступы, иконки и любые хардкод-пиксели масштабируются вместе. Высота viewport заранее делится на активный zoom, чтобы оболочка оставалась ровно по размеру viewport.
- **Визуальный редизайн v2** (PR #55). Главная страница, разметка master/detail, деревья настроек (устройства, профили, процессы, аудиты, хосты, рабочие места, workbench'и), карточка операции и панель управления переходят на новые design-токены, переключатель плотности и контролы темы/схемы, общие с Console и Логистикой. Секции редактора, сетка свойств и встроенные формы переходят на примитивы на базе `Field`; пустые / ошибочные / загрузочные состояния получают единое представление. См. `docs/design-handoff-notes-v2.md` и вложенный `Edm design-handoff v2.zip` как первоисточник.
- **Исправления UX master tree-view** (PR #45). Стилизация detail-панели и tree-view в деревьях настроек скорректирована, чтобы выделения и компоновка панели вели себя как задумано.
- **Исправление запуска операции** (PR #42). Запуск операции из меню Operation снова работает стабильно — обвязка меню больше не теряет действие запуска.

## v1.13.28

- **Исправление выбора процесса в мастере New Operation** (PR #41). Выбор процесса снова надёжен, когда папка и процесс случайно совпадают по числовому id — picker теперь использует префиксированные значения (`process-…` / `node-…`), поэтому управляемое состояние не «зацепляется» за отключённую строку папки.

## v1.13.0

- **Доводка панели управления** (PR 793, 795, 796, 797, 798, 800). Операции окрашены по статусу; список завершённых сегодня отфильтровывает вчерашний шум; корневая панель разворачивается до выполняющихся операций по процессам; отменённые строки показывают, *когда* были отменены; добавлено представление завершённых за 7 дней; строки сортируются по дате завершения/отмены.
- **Контекстное меню и копирование операции** (PR 783, 804). Правый клик по операции открывает её, отменяет или копирует; любую завершённую операцию можно использовать как seed для новой одним кликом.
- **Исправления редактора и алертов** (PR 754, 755, 765, 790). Редактор опций драйвера рендерит правильную схему даже после замены драйвера устройства, popup редактора критерия сохраняет значения при прокрутке, поля, отключённые условием, по-прежнему сохраняются, а алерты можно закрывать, и они больше не блокируют страницу.
- **Последние измерения сенсоров в отчёте** (PR 748). Отчёты показывают самое свежее измерение по каждому сенсору, а не произвольный отсчёт из середины выполнения.
- **Более плавный старт операции** (PR 784). Статус меньше мигает в окне запуска, потому что задачи и устройства инициализируются до завершения мастера.
- **Обработка поставок** (PR 715). Редактирование и потребление поставок, привязанных к процессу, прямо из основного UI.
- **Редизайн UI технологий** (PR 825). Переорганизован вокруг производственных процессов, со сгруппированными вместе сортами и спецификациями; legacy-вид заменён — закладки могут потребовать обновления.

## v1.12.5

- **Исправления сохранения** (PR 589, 590). Правки опций драйвера теперь сохраняются, а параметры, набранные в мастере, доходят до устройства при старте.
- **UX карточки операции** (PR 586, 666). Отдельный × на карточке операции для её закрытия без потери прокрутки; отвязка процесса от рабочего пространства отражается сразу.
- **Обработка дат** (PR 680, 681). Backend хранит метки времени в UTC; UI показывает их в локали пользователя.
- **Auth-дружественные ресурсы и более тихая консоль** (PR 628, 667, 668). PWA-манифест доступен и в авторизованном, и в неавторизованном потоке; фантомная ошибка web-worker'а при каждой навигации устранена.
- **Более быстрое погружение в сенсор** (PR 684, 690). Страницы сенсоров запрашивают один сенсор по требованию, а не отчёт целиком.

## v1.12.0

- **Мастер New Operation доведён** (PR 567, 604). Мастер надёжно переносит выбранный workbench / устройство к запуску; перезапуск больше не создаёт дубликат операции.
- **Функция «equals» в аудите** (PR 579). Аудиты могут сравнивать два параметра на равенство, а не только диапазоны.
- **Вкладка зон аудита в карточке** (PR 573). Зоны — соседняя вкладка карточки операции, а не закопаны в опциях аудита.
- **Универсальная панель управления** (PR 558). Карточки операций используют ту же панель Start / Cancel / Done, что и приложения операций.
- **Подразделения пользователей** (PR 608). Фильтрация операторов по подразделению заменяет прежнюю ad-hoc проверку роли.
- **Исправление списка активных хостов** (PR 610). Живые хосты отображаются как живые; регрессия со stale-кэшем устранена.
- **Исправление переключения роли** (PR 568). Переключение роли корректно перерисовывает меню.
- **Скрыты удалённые рабочие места в picker'е старта процесса** (PR 578).

## v1.0.0

- **Начальная оболочка** (PR 218, 226, 228). Рабочие места, операции и секции настроек, которые расширяют другие плагины.
- **Связка workbench / процесс** (PR 368, 371, 372). New-Operation предлагает только устройства, чей профиль допускает выбранный процесс; профили различают входные и выходные параметры, и мастер собирает только входные; профиль, привязанный к workbench, виден в строке устройства.
- **UX жизненного цикла операции** (PR 284, 422, 498). Карточка операции показывает опции устройства, активные на момент старта; брошенные операции можно принудительно завершить из карточки; правки в другой вкладке шлют уведомления всем, у кого открыта карточка.
- **Аудит по шаблонам** (PR 294). Зоны аудита берутся из шаблона, который вы редактируете однократно, вместо копирования из операции в операцию.
- **Обновление UI** (PR 367, 382, 386). Bootstrap 5 / Kendo React 5 на сайте; drag в tree-view больше не выделяет половину текста страницы; ведущий `0` в поле детали процесса больше не «съедается».
- **Исправление привязки хоста** (PR 380). Привязка хоста к устройству сразу обновляет строку устройства.
- **Точки входа в оператор-десктоп** (PR 432, 435). Кнопки в основном UI запускают UI оператора и общее приложение оператора Optosense.
- **Доводка интеграции ISL** (PR 431). Связки с системой ISL работают сквозным образом со стороны основного UI.
