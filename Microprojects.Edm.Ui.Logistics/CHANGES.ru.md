# Логистика — изменения для пользователей

Приложение «Логистика» (`/logistics`) охватывает номенклатуру, тару, поставки, изделия, заказы, перепаковку, распределение, оператор-десктоп и дерево производственных процессов. Появилось в v1.13.0 и остаётся в фокусе большинства недавних работ.

## v2.0.0.0

- **Обновлённый внешний вид по всему приложению.** Главные экраны, оператор-десктоп, деревья настроек (Номенклатура, Типы тары, Процессы) и потоки изделий / заказов / распределения теперь используют те же шрифты, плотность и цветовую схему, что Технологии, Консоль и Хаб. <!-- cite: PR #58 -->
- **Add Item / Add Folder больше не падают с ошибкой «Failed to load data».** Создание новой Номенклатуры, Типа тары или Процесса с кнопки Add в master-дереве (или из действия Add в пустом состоянии) открывает редактор корректно. <!-- cite: PR #58 -->
- **Добавление новой строки в таблицах связей снова работает.** Номенклатура ↔ Типы тары, Сорта / Спецификация / Подпроцессы у процесса, Спецификация заказа — кнопка «Add record» теперь создаёт строку, а не падает. <!-- cite: PR #58 -->
- **Спецификация заказа — клик по строке компонента открывает панель распределения.** Клик по строке на вкладке Спецификация снова работает. <!-- cite: PR #58 -->
- **Новый заказ — автоинкрементный № заказа снова подставляется.** Панель Create-new показывает следующий по порядку номер при открытии редактора. То же исправление работает при переключении между элементами в master-дереве. <!-- cite: PR #58 -->
- **Поиск компонента — строки тары снова раскрываются.** В панели поиска, открытой из строки Спецификации заказа, «шеврон» переключает каждую тару, раскрытый вид показывает ту же схему тары, клик по слоту выбирает изделия, а двойной клик по строке тары распределяет тару целиком. <!-- cite: PR #58 -->
- **Спецификация заказа — переключатель «Скрыть полностью распределённые» теперь встроен.** Переключатель находится в панели инструментов таблицы — поиск слева, переключатель справа. <!-- cite: PR #58 -->
- **Вкладки заказа — Спецификация и Операции теперь только для просмотра.** Обе вкладки отображаются как обычные таблицы, без кнопки Add и без колонки действий по строке. <!-- cite: PR #58 -->
- **Ссылка «Заказы» в шапке по умолчанию открывает «Активные».** Клик по «Заказы» теперь ведёт на /orders/ongoing с подсвеченной вкладкой Active. <!-- cite: PR #58 -->
- **Деталь заказа — карточка и редактор переорганизованы.** Карточка просмотра теперь показывает даты Start и Due и описание рядом с Amount, Номенклатурой и Процессом — больше не нужно переходить в режим редактирования, чтобы прочитать расписание. В редакторе Amount находится рядом с выбором процесса, чтобы «что делать» и «сколько» заполнялись вместе. <!-- cite: PR #58 -->
- **Поиск заказов обновляется при удалении заказа.** Удалённые строки больше не висят в списке поиска. <!-- cite: PR #58 -->
- **Спецификация заказа — у каждого заказа теперь своя копия спеки процесса.** Компоненты в уже запущенных заказах больше не меняются при последующих правках процесса или его номенклатур. Компоненты, чья номенклатура удалена или завершена, пропускаются при создании. Заказы, созданные до этого изменения, стартуют с пустой вкладкой Спецификация — строки нужно добавить однократно. <!-- cite: PR #58 -->
- **Allocate / Repack — выбор по штрих-коду добавляет тару одним шагом.** Сканирование штрих-кода в Allocate Output или Repacking сразу опускает тару в рабочую область (с автосозданием по типу тары по умолчанию для заказа, если штрих-код новый), так что сканирование идёт от ввода до заполненного целевого слота без лишнего клика. <!-- cite: PR #62 -->
- **Схема тары — клик по изделию открывает его карточку.** Изделия в таре (на странице Items и внутри детали Тары) теперь открываются в read-only-панели рядом с тарой, чтобы можно было просмотреть историю изделия, не покидая представления тары. <!-- cite: PR #63 -->
- **Sub-detail-панели закрываются после успешного удаления.** Sub-detail-панели Тары и Изделия, открытые с родительского экрана — и встроенные панели, открытые из таблиц связей — больше не оставляют устаревший контент после удаления. <!-- cite: PR #66 -->
- **Перетаскивание в master-дереве приземляется в осмысленное место.** Drop на пустое пространство вне любой цели раньше ничего не делал; теперь перемещение делает fallback на видимый локальный корень. Удаление папки также сразу обновляет дерево. <!-- cite: PR #70 -->
- **Хлебные крошки во вложенных Detail-панелях.** Каждая Detail (и каждая sub-detail из её строк) показывает путь к родительским записям, так что путь «Заказ → Тара → Изделие» виден в верхней части глубокой панели. В пути также используются корректные множественные имена (Процессы, Типы тары). <!-- cite: PR #72 -->
- **Деталь поставки — Компоненты теперь обычная вкладка связей.** Изделия внутри поставки отображаются в плоской таблице с поиском в панели инструментов и кнопкой «Add items» справа; клик по строке открывает карточку изделия рядом, как на других вкладках. <!-- cite: PR #73 -->
- **Генеалогия изделия — панель Inputs читается справа налево.** Текущее изделие находится справа, а предки уходят влево, в соответствии с естественным направлением чтения «откуда это?». Outputs по-прежнему текут слева направо от текущего изделия наружу. <!-- cite: PR #74 -->
- **Спецификация заказа — Required / Allocated отображаются как корректные числа.** Полностью распределённые подсчитываемые номенклатуры больше не отображаются как `0.9999999999999999`; подсчитываемые строки округляются до целых, дробные — обрезают хвостовые нули. <!-- cite: PR #58 -->

## v1.13.28

- **Перепаковка — Reset и видимость исходной тары.** Reset возвращает pending-перемещённые изделия в исходные слоты. Строка исходной тары остаётся видимой, пока все её изделия перемещены наружу, чтобы было видно, что вы убрали, и можно было вручную очистить тару, когда закончите. <!-- cite: `550d3bb` -->

## v1.13.27

- **Подвал с версиями и «Что нового».** В подвале оболочки теперь видны версия плагина, версия продукта EDM и ссылка на пользовательский журнал изменений. <!-- cite: `c4d54f7` -->
- **Единое распределение и перепаковка.** Allocate Output, Перепаковка и схема тары используют общий механизм выбора-и-перемещения с контекстным меню, легендами сортов и номенклатуры и одним фильтром видимости — выбор исходных изделий и сброс на целевую тару работают одинаково во всех потоках. <!-- cite: `a466381` -->
- **Автоинкрементный номер заказа.** Новые заказы получают последовательный номер при сохранении с сохранением формата предыдущего заказа (`1`, `2`, …, или формы с префиксом и ведущими нулями, например `ORD-0043`). Деталь заказа показывает его как заголовок `#<номер>`, и он отображается в списке заказов десктопа, детали изделия и узлах генеалогии. Заказы без положительного Amount отвергаются при сохранении с понятной ошибкой. <!-- cite: PR 28, PR 35 -->
- **Доводка UX заказов.** Список заказов обновляется при создании или завершении заказа; после успешного Create правая панель переключается с формы New-Order на просмотр только что созданного заказа; целевой тип тары в allocate-output подставляется из значения по умолчанию для номенклатуры; панель тары, открытая из вкладки заказа, соответствует сводке строки, а не дублирует split'ы распределения; пустая вкладка Output показывает «Ещё не выполнено» вместо пустоты. <!-- cite: PR 31, PR 32, PR 33, PR 34 -->
- **Редизайн генеалогии изделия.** Узлы дерева генеалогии показывают детали изделия при наведении, рёбра окрашены по происхождению (output, store, supply, split), а изделия, созданные напрямую без поставки или предка, помечены происхождением «store». <!-- cite: PR 30 -->
- **Жизненный цикл изделия — количество остаётся неизменным.** Количество изделия фиксируется при создании и никогда не уменьшается — потребление отслеживается отдельно — поэтому выполненные заказы сохраняют исходное распределение видимым в истории, расчёты заполнения тары и распределения заказа корректно учитывают частично потреблённые изделия, а шум счётчика изделий в уведомлениях устранён. <!-- cite: `8fd3ce9` -->
- **Даты и время в вашей локали.** Поля дат и дат-времени в заказах, поставках, оператор-десктопе, деталях папки и таблицах связей отображаются в вашей локали; время больше не «дрейфует» на ваш локальный сдвиг. <!-- cite: PR 27 -->
- **Корень по типу.** Номенклатура, Тип тары и каждый вид процесса (Manufacturing, Technology, Operation) открываются на собственном предварительно засеянном корне дерева каталогов, чтобы новая запись попадала под правильный корень автоматически. <!-- cite: PR 26 -->
- **Версионирование типов тары, номенклатур и процессов.** При сохранении нетривиальной правки одной из таких сущностей, у которых уже есть живые или исторические ссылки, UI предлагает форк — правка становится новой версией, оригинал замораживается, а существующие изделия, заказы и история продолжают рендериться против той версии, при которой были созданы. Тривиальные правки (Имя, Описание) по-прежнему меняют сущность на месте. Picker'ы и master-дерево показывают только текущую версию, поэтому старые форки не появляются как дубликаты в списках выбора. <!-- cite: PR 24, PR 37 -->
- **Кросс-пользовательское обновление и блокировки.** Изменения, сделанные другим пользователем, распространяются в ваши открытые виды; Copy и Delete в панели Detail отключаются (с подсказкой «Locked by …»), пока блокировкой владеет другой пользователь; кросс-сообщения о папках корректно инвалидируют каждый leaf-вид, а не только тот, что соответствует типу самой папки. <!-- cite: PR 19, PR 22, PR 23 -->
- **Исправления перетаскивания в master-дереве.** Цели drag-and-drop разрешаются относительно видимого (отфильтрованного) дерева, а не сырых данных, чтобы drop попадал в нужную папку; навигация между видами процесса больше не сбрасывает новые элементы в папку предыдущего вида. <!-- cite: PR 20, PR 21 -->

## v1.13.22

- **Стартовые данные на пустой БД.** Стандартные номенклатуры, типы тары и процессы засеваются по умолчанию, чтобы приложение было готово к работе из коробки; миграции базы выполняются автоматически. <!-- cite: PR 4, PR 15 -->
- **Фильтрация тары и происхождение «store».** Операторы видят только те типы тары и штрих-коды, которые допускает активная номенклатура и разрешают группы пользователя; изделия, созданные напрямую (без поставки, без выпускающего процесса и без link'а к родителю), помечены происхождением «store» в детали изделия и дереве генеалогии. <!-- cite: PR 11, PR 12, PR 14 -->
- **Качество picker'ов.** Все picker'ы каталогов используют иерархический drop-down tree, учитывающий политики групп пользователей; всплывающие окна расширяются до самой длинной записи, чтобы значения не обрезались. <!-- cite: PR 10, PR 13 -->

## v1.13.0 — первый релиз

### Каталоги
- **Каталоги номенклатуры и тары.** Полное создание / редактирование / удаление номенклатуры и типов тары с дробными количествами и единицами, отображаемыми встроенно, плюс двунаправленная связь между ними — редактируйте связь с любой стороны. <!-- cite: PR 711, PR 712, PR 727, PR 734, PR 9 -->
- **Пустые папки скрыты в picker'ах.** Поддерживает читаемость дерева каталогов. <!-- cite: PR 826 -->

### Процессы и спецификации
- **Дерево процессов.** Каталог производственных процессов с типом, родителем и конфигурацией; на каждый процесс вкладка спеки и сорта для технологических процессов; процессы представлены отдельными деревьями по виду со скрытыми корнями; picker родителя предлагает только разрешённые дочерние типы; в Settings по умолчанию открывается дерево Manufacturing; picker для нового заказа — дерево, а не плоский список. <!-- cite: PR 708, PR 716, PR 824, PR 827, PR 828, PR 831, PR 833, PR 835, PR 836 -->
- **Исправления процессов.** Обработка вида процесса и фильтров групп каталогов работает согласованно. <!-- cite: PR 829, PR 834 -->

### Поставки и изделия
- **Поставки и изделия.** Приёмка поставок и привязка их к процессу; Поставки и Изделия — отдельные страницы со своими фильтрами; изделия используют стандартную разметку master/detail; переключение между доступными и потреблёнными; полное дерево происхождения (генеалогии) для любого изделия; выходные изделия можно сортировать по сортам; разделение изделия работает с дробными количествами в спеке; правки create и update сохраняются надёжно. <!-- cite: PR 715, PR 724, PR 725, PR 733, PR 832, PR 840, PR 841, PR 842 -->

### Заказы, перепаковка, распределение
- **Заказы.** Просмотр и редактирование заказов с их строками и привязками процессов, выполнение операций, обслуживающих заказы, резервирование конкретных изделий, переключение между активными и завершёнными, ограничение формы нового заказа процессами типа «операция», сохранение правок, затрагивающих несколько процессов, и переорганизованная панель деталей со скалярными полями и табулированными таблицами связей. <!-- cite: PR 720, PR 721, PR 722, PR 726, PR 731, PR 736, PR 843, PR 845 -->
- **Распределение.** Выбор изделий для распределения по строкам заказа в модальном окне, чтобы не терять контекст. <!-- cite: PR 839, PR 846 -->
- **Перепаковка.** Перемещение содержимого из одной тары в другую с порождением итоговых изделий; picker тары отражает то, что физически находится в таре, включая штрих-коды. <!-- cite: PR 3, PR 838, PR 849 -->

### Оператор-десктоп
- **Оператор-десктоп.** Однооконный UI для цеха, чтобы принимать, перепаковывать и завершать операции; изменяемые master/detail-панели; шаг Done закрывает активную задачу; алерты валидации появляются над формой, а не сдвигают её вниз. <!-- cite: PR 7, PR 8, PR 735, PR 847 -->

### Авторизация
- **Вход и группы.** Логистика использует общий поток входа платформы; пользователи принадлежат нескольким группам, и права суммируются. <!-- cite: PR 758, PR 819, PR 823 -->

### Полировка и инфраструктура
- **Полировка.** Начальные макеты страниц и навигация с выравниванием иконок; длинные каталоги используют ленивую загрузку сеток вместо пагинированных; проект чисто запускается в dev и production без per-developer-конфигурации. <!-- cite: PR 709, PR 710, PR 713, PR 714, PR 816 -->
